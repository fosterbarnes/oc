Use this tool when you need to ask the user questions during execution. This allows you to:
1. Gather user preferences or requirements
2. Clarify ambiguous instructions
3. Get decisions on implementation choices as you work
4. Offer choices to the user about what direction to take.

Ask only when a missing answer materially changes scope, correctness, or a consequential choice, and the code cannot answer it; otherwise pick the smallest sensible default. Once you do need an answer from the user, ask it with this tool rather than in plain text, including open-ended questions. Explanations, rhetorical questions, and answering the user's own questions do not need it.

Usage notes:
- The form always includes a "Type your own answer" field; don't include "Other" or catch-all options
- For an open-ended question, pass `options: []`; don't invent choices just to fill the list
- Batch related questions into one call
- Answers are returned as arrays of labels or typed text; set `multiple: true` to allow selecting more than one
- If you recommend a specific option, make that the first option in the list and add "(Recommended)" at the end of the label
- Wait for the answer. If the user dismisses the form, treat that as no answer: do not guess or repeat the question in plain text
