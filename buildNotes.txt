v0.2.157 discoloredDebt

oc and opencode:
oc and occ use the background server, while the separate native opencode program runs in its own window from the same source. The oc single command, single and portable launch flags, and mode setting are removed; use opencode for native sessions. Revive from a native window reopens opencode with the same directory and session.

build and install:
Build and install scripts accept -Oc or -Native to handle either program. Installation breaks the old shared hard links, keeps occ linked to oc, and verifies that opencode is separate. The run script opens oc by default and accepts -Native for opencode. Project rules, the README, fork status, script reference, and native split plan reflect the two programs.

palette launch:
Launching a palette entry opens the sibling native opencode executable instead of repeatedly spawning the oc launcher. The native TUI keeps its executable-scoped ledger and revive shutdown acknowledgement.

Under the hood: Global.native selects the build flavor; executable resolution maps only occ to oc; startup, TUI, footer, and revive paths use the native flavor instead of OC_SINGLE. Build outputs include separate oc and native executables, with ocdebug available for debug builds. Checks passed: core global.test.ts, opencode revive.test.ts, and git diff --check, plus the agent-push pre-push checks. Earlier session verification recorded clean opencode, tui, and core type checks and command-loader tests; the user verified distinct installed binaries after the second revive. Bun-dev native revive environment propagation through Windows Terminal remains unverified.
