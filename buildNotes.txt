v0.2.108

keybind layouts:
oc now has two key layouts: oc (the default, your layout) and opencode (stock OpenCode keys), chosen with "keybind_preset" in tui.json or with Keybind layout in the oc section of the command palette (or /keybindLayout). The palette switch takes effect at once and is remembered in global tui.json. In the oc layout ctrl+m opens the model list, ctrl+s the session list, ctrl+d cycles the model variant in the prompt and deletes the session in the session list, and ctrl+c clears the prompt instead of quitting. Quitting stays ctrl+x q. Where your key replaces an opencode leader key, the leader key still works too (ctrl+x m for models, ctrl+x l for sessions). A new docs/keybinds.md lists every key for both layouts with differences in bold.

revive mark:
After a revive that installs a new build, the [oc revived at ...] line now shows the version that came back instead of the version that wrote it. Confirmed live: the line read oc v0.2.108 after installing 0.2.108.

Under the hood: keybind.ts matches upstream defaults again apart from oc-added commands, and the oc layout lives in one override table applied under user keybinds. Switching layouts also re-registers the prompt editing keys (ctrl+a, ctrl+d delete, ctrl+shift+up/down) at once; open dialogs keep old hints until reopened. A project-level tui.json keybind_preset overrides the saved global choice on next start. The docs tables are generated by packages/tui/script/keybindDocs.ts and prePush fails if they are stale. The revive mark is rewritten once on session open when the newest message is still an unsent revive mark with a mismatched version. This push's focused checks passed: tui typecheck clean, opencode package typecheck clean, config/keymap/prompt-background/terminal-win32 tests pass, keybind docs check passes. Live layout switching in the running TUI was not run.
