v0.2.156 crudFlick

claude usage sidebar:
Known hourly and weekly Claude percentages stay visible when a reset date is missing or a usage refresh returns only part of the data. Windows that have passed update locally without sending Claude a message, and missing next-reset dates leave blank slots. Cached readings stay identified as last-known, including after a restart, and genuinely unknown percentages still show unavailable. A Claude account with no 5-hour window running yet shows "-" under its 0%h, and with several accounts idle ones show "-" while active ones keep their reset time, all on one row.

sidebar scripts and files:
Script and file rows keep their clipping stable when the same list refreshes during a response, real script settings and file-list changes still update, and extremely narrow rows stay within their text budget.

context limit handoff:
When a session crosses the token threshold in Handoff mode, the follow-up session continues the work instead of stalling and keeps the permissions of the original turn. The work-preservation summary runs fully locked down while still reaching the live conversation. A non-numeric token threshold in the TUI dialog is rejected.

Under the hood: usage.ts parses Claude hourly and weekly windows independently with projectClaudeUsage and updateClaudeSnapshot, and keeps per-window reading times in cache metadata; sidebar helpers reconcile script and tree rows by key; isTitleRequest keys on naming agents and tool-less turns under a session agent share the chat's tools:: conversation key; handoff.ts, work-handoff.ts and work-done.ts are new, along with the SDK regeneration and config changes. Checks passed: usage-freshness (31 pass), sidebarRows (5 pass), title/handoff/overflow/v2-compat tests, and the fake-model handoff tests. Live sidebar, TUI and Cursor checks were not run.
