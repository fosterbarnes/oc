v0.2.363 eloteLem [fix > queued edit on non-Claude models]

messages sent while the agent works:
On models other than Claude Code, Edit and Delete on a QUEUED message now work until the model's next call picks the message up. Before, they always failed while the agent was busy. Once the next call has read the message, taking it back is refused with the same "Too late to take back" notice as on Claude.

clipboard tool:
Asking an agent to copy two separate code blocks no longer pastes half-broken fences; a single fenced block is still copied without its backticks. If clicking a "Copied" row fails to copy, oc now says so instead of failing silently.

Under the hood: each step of oc's own loop builds every model request from one read of the session. That read now runs under a per-session lock and records the newest message it saw (new session/intake.ts). The delete route still asks a running Claude turn first; otherwise it removes a user message only if it is newer than the latest read and that step runs on oc's own loop, under the same lock, so a message is either read or removed, never both. The clipboard tool unwraps a code fence only when the text is a single block, and the clipboard row's copy now catches errors. The sidebar Claude pool test no longer reads the Mac's real Keychain login. Docs: wiki Sessions.md, FORK.md steering row, and the queued-edit plan marked resolved.
