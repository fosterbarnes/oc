v0.2.345 poopingPerms [fix > Claude no-reply note; feat. > Fable 5.2]

claude chats:
Sending a message right after oc or Claude Code restarted, while a Claude background command was still running, no longer shows a false "no reply" note before the real answer. Claude Code reports the stopped command as a turn of its own before it reads your message, and oc took that empty turn for the reply.

When a slash command or a model, agent, or effort change restarts Claude Code and that stops background commands it was running, the reply now starts with a note saying how many were stopped and why. The restart itself is unchanged, so slash commands keep their tool restrictions.

claude models:
Claude Fable 5.2, Fable 5.2 Fast, Mythos 5.2, and Mythos 5.2 Fast appear in the Claude Code model list, with Fable 5.2 priced at 8x (Fast 16x). Without Mythos access, a Mythos 5.2 turn tells you to pick Claude Fable 5.2 instead. Run claude update to get Claude Code 2.1.321 or later, which knows Fable 5.2.

Under the hood: a result whose origin is a task notification is skipped unless the turn attached to a turn the CLI started on its own. Mythos 5.2 is built as a twin of Fable 5.2 because the catalog does not list it. buildNotes.md was rotated to buildNotes.archive16.md. New tests: a silentTurn case, a fake-model scenario for a restart with a running background task, and a configModels case for the 5.2 models. Checks: probes on Claude Code 2.1.321 against the fake model reproduced the false note and showed it gone; silentTurn, autonomousTurn, respawn, cliEvents, and sessionManager tests pass (74); configModels passes (8); typecheck is clean. fakeModel.test.ts has its 3 known macOS failures.
