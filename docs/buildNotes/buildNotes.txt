v0.2.253 englandMachismo

claude forks:
Forking a Claude chat (Ctrl+P > fork) now continues the same Claude Code conversation in the fork instead of asking to start a new one. The original chat keeps its own Claude conversation, and the two branch from the fork point. Forking from an earlier message rewinds the fork's Claude conversation to that point; if that point is too far back, the fork starts a new Claude conversation with the last exchange.

warm-up schedules:
Save preset keeps named daily or weekday schedules for reuse across accounts and restarts. Load preset copies the times into the editor; press Save to activate them for that account. Reusing a name asks before replacing it, and saving a preset leaves active schedules alone. Esc in the schedule editor now goes back one screen at a time to the menu that opened it, and Esc on "Replace preset?" returns to the name prompt instead of closing the editor.

menus:
Pressing Esc to go back now returns to the item and search you had in every menu with a back step, including the command palette and the model picker's screens, and the list scrolls straight to that item.

usage:
Show usage now appears in the oc command palette under Third party harness management while a session is open.

Under the hood: forked oc sessions copy the origin's Claude session records with a pending-fork flag, so the first spawn adds --fork-session and the origin's transcript is never written by the fork. Dialog selection memory is shared through each screen's parent, and explicit list moves cancel pending deferred scrolls. Warm-up presets use strict validation and locked read-modify-write storage. Recorded checks passed: sessionSync.test.ts (8 pass) and cliArgs.test.ts, opencode typecheck, full tui bun test (635 pass, 2 known subagentDialog failures), claudeWarmup.test.ts, claudeWarmupRendered.test.tsx, usagePalette.test.ts, tui typecheck, and git diff --check. prePush runs on this push. Live checks of forked Claude chats and warm-up presets in the installed app remain with the user.
