v0.2.330 gggggWings [fix > Claude account handoff; perf. > model list]

claude accounts:
A /revive or restart no longer switches your Claude account on its own. Only a real usage-limit rejection or your own pick changes it; before, a stale usage cache could mark the current login limited at startup and move every chat to another account.

When your Claude logins share one projects folder, a chat that moves to another login keeps its Claude Code conversation and full memory, also when it moves back later, and a mid-turn usage switch continues with a one-line "continue" instead of a catch-up summary. The new .scripts\shareClaudeProjects.ps1 moves existing logins to the shared folder (dry run first, -Apply to move), and new accounts made in Claude accounts link the shared folders automatically.

oc, native opencode, and test windows now see each other's Claude account picks and conversation records instead of overwriting them, so a revive no longer brings back an account another window replaced.

claude chats:
A turn Claude starts by itself after a background task, for example a build finishing during /agentTest, now keeps the slash command's tool permissions, so tools the command allows no longer fail with "Unknown tool".

model list:
Typing in the model list keeps up with your keys: each key took about twice as long as in the command palette because every keystroke rebuilt every provider's model rows.

dialogs and sidebar:
A list dialog with a long title, such as "Switch Claude account (this session)", no longer paints over its esc hint. Hiding and showing the sidebar keeps the usage numbers on screen instead of flashing "unavailable" until the next fetch.

agent testing:
nativeTest.ps1 now saves the shared settings a test window can change (model pick, kv settings, current agent, palette history, tui.json, Claude account pool) when it starts and puts back any that changed when it stops, listing what it restored. /agentTest saved screens show the state each case judged. The /agentTest tester, with new reply and pick steps and a recipe file kept in the user config, now does every basic oc action right on the first try: 3 of 3 rounds per action group, no wrong PASS.

Under the hood: wake turns inherit the previous user message's rules in session/prompt.ts; the account pool and Claude session files reload when another process changed them. Checks that ran: test/provider/claude-code 696 pass 0 fail and test/session/prompt.test.ts 72 pass (from PowerShell), accountPool 26 pass, failoverQuestion/silentTurn/warmup 54 pass, opencode and tui typecheck clean, tui model-options/dialog-select/dialogSelectSessionMarkerActions/claudeWarmupRendered/openSidebar/usageFreshness 142 pass, shareClaudeProjects.ps1 dry run on the real profile and -Apply on a temp copy, and the three TUI fixes checked on a rebuilt native window (model list 165 to 85 ms per key).
