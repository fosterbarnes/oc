Windows edit denials for Claude:
On Windows, a command that blocks edits to certain folders (such as an implementation command that denies a mockups folder) now lets Claude use its own Edit and Write tools, with the blocked folders passed to Claude as its own deny rules. Before, any Windows path in such a rule sent every edit through oc's proxy, so Claude had no native Edit or Write on those turns.

Under the hood: session/llm/request.ts `claudeEditDenies` runs each pattern through the new `claudePosixPath`, which turns `C:\a`, `C:/a`, and the mixed `C:\Users\u/.config/...` that `~` expands to on Windows into Claude's `/c/a` form, then sends `Edit(//c/...)`. Test fix: test/session/prompt.test.ts "typed messages inherit the active command permission" now uses a git repo (`{ git: true }`), because on Windows the temp dir sits under the profile and the `.opencode` config walk picked up the real `~/.opencode/commands/imp.md`. commandToolPlan.test.ts moves `C:/a/**` from the oc-only cases to a translated case. FORK.md updated.

Checks: macOS `tsgo --noEmit` clean; `test/provider/claude-code/` + `test/session/` 1367 pass 29 skip 0 fail. Windows 10 (goonstation): commandPermissions (real Claude CLI enforced the `//c/...` deny), commandToolPlan, replacedToolsNote and the prompt test pass 3/3 runs; `test/provider/claude-code/` + `test/session/` 1356 pass 41 skip 0 fail. Before the fix, v0.2.388 failed those two tests 3/3 on Windows; the rest of the recent-change set (tui, core, pane) passed on both machines.
