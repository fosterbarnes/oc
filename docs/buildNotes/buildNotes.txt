v0.2.362 songyBird [fix > Mac sidebar scripts; scripts > shellbench]

sidebar scripts:
On macOS, sidebar scripts set to open in a WezTerm tab, window, or split now start; before, they failed with "WezTerm exited with code 2". They work whether WezTerm's default shell is PowerShell or zsh: oc waits for the new pane's prompt and types the command in that shell's syntax.

agent shell:
When an agent runs PowerShell commands on macOS, oc no longer loads your PowerShell profile for each one, which makes each command about 0.15 s faster and stops profile functions (such as a custom kill) from changing what commands do. Restart oc (/revive) to pick this up.

developer tooling:
New benchmark .scripts/shellbench compares pwsh with the Mac's built-in shell on agent commands, version bumps, single-package test runs, and the clone scripts, with identical results on both; docs/dev/shellBenchReport.md has the timings and recommendations. .scripts/posix holds plain-shell copies of bumpVersion and the single-package test runner for that comparison; the PowerShell scripts are still the ones to use.

Under the hood: the shell tool now passes -NoLogo -NoProfile -NonInteractive to pwsh on every OS (was Windows only). The sidebar runner maps wezterm-gui to wezterm on every OS, waits until the new pane's terminal settles at its prompt (up to 5 s), and picks pwsh or POSIX quoting from the pane's shell. docs/dev/macos.md now names the Mac ssh alias and says goonstation has no file shares. The Mac's unpushed work was renumbered from a colliding 0.2.361 to 0.2.362 after taking the Windows commit. Checks: shell, backgroundShell, and shellMetadata tests 44 pass on zsh, and 44 pass 2 fail on pwsh with both failing the same way without the change (POSIX-only commands); openSidebar 79 pass when the change was made, now 78 pass 1 fail on this Mac from a known Claude pool usage test that reads the real macOS Keychain login (79 pass with CLAUDE_CONFIG_DIR set); tui typecheck clean; live WezTerm probes ran the script in 8 of 8 pwsh and 3 of 3 zsh panes; every shellbench case gave the same output on both shells, also with pwsh off PATH. Not checked: Windows.
