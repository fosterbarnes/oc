updating oc:
/update works again. oc ships no executable releases yet, so for now /update brings the source folder that /revive builds from up to the latest GitHub main, then builds, installs, and reopens like /revive. If that folder has changed files or commits that are not on GitHub main, /update lists them (first five files and the commit count) and asks before discarding them; files git does not track are kept. A folder on another branch is refused with a message, and when the folder and the installed oc already match main it says "oc is up to date" without restarting. The release download path stays in place, unused, until releases ship.

dev docs:
Windows and the Mac are now both full dev machines, each with its own git clone synced only through GitHub; the rsync mirror notes in docs/dev/macos.md are retired. The wiki's Updating oc and dev/stable install sections describe the new /update. The 0.3.0 checklists drop the /agent-revive-no-install live check.

Under the hood: new core/util/ocSource.ts fetches main by URL and reports branch, dirty tracked files, and ahead/behind, and resets only to the commit the user confirmed, under the same build lock as /revive, with git credential prompts off. The revive prepare request gains an update commit field. Checks: ocSource tests 3 pass (new, guard the warning before a destructive reset), revive config tests 19 pass, tsgo clean in core, opencode, and tui; a live probe against GitHub listed exactly the edited files. Live /update in the TUI not run yet.
