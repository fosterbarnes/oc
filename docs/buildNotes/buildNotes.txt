v0.2.343 outgoingStallion [patch > /revive builds in the background]

revive:
/revive now builds oc in the background while you keep working. The window closes only for the swap at the end: a few seconds after a build, and well under a second when nothing changed. A failed build shows the last lines of its log in an error notice, and your window stays open (a revive chain gets its steps back). If you start a reply while the build runs, the restart waits for it. /update downloads the new release the same way.

When the source folder has not changed since the installed build, /revive skips the build entirely and just restarts and reopens your tabs.

builds:
A /revive build takes about half as long: oc is compiled once and copied for opencode, the cross-platform package installs are skipped, and the model list comes from oc's own cached copy, so /revive also works offline. On macOS, the reopened window and the first native opencode window no longer wait about 1.5 seconds each after a revive. bun.lock and package.json no longer show as modified in git after a revive.

removed:
The revive.path custom script setting and the .scripts revive scripts are gone; the built-in restart does the same job. A leftover revive.path key is ignored.

Under the hood: revive is split into prepare (oc oc --revive-prepare, ReviveHost.prepare: source choice, skip check, bun install and build into a staging folder in oc's cache under a build lock, or the release download) and swap (the existing pipeline, which now only installs ReviveContext.output, restricted to paths inside oc's cache; the update mode and source fields are gone). The installed oc carries a baked git tree hash of its source (core/util/sourceTree.ts, OPENCODE_SOURCE_TREE) for the skip check. Global.native now follows the executable name (opencode is native, oc/occ are oc, anything else reads OC_FLAVOR), which replaces the OPENCODE_FLAVOR build constant; build.ts clones the compiled binary for native, takes --outdir, and prints phase timings. Measured on the Mac: whole prepare 5.6 s (was about 11 s with the window closed), compile 3.5 s, clone 0 ms. Most of the old 2.3 s server start was the macOS first-launch scan of each new executable path (about 1.6 s per name; plain oc serve answers in 0.26 s), so the swap now warms occ and opencode while the server starts. The legacy shell revive tab kind is removed, and the restarter no longer logs a failure when a single-tab window's WezTerm socket is already gone. src/bun.lock is marked eol=lf because Bun writes LF on every OS.

Checks: typecheck clean in core, opencode, tui; core sourceTree.test.ts 4 pass; opencode revive.test.ts 19 pass, 11 skip (Windows-only, not run); opencode test/config 321 pass with 1 failure unrelated to this change (tui.test.ts "resolves keybind lookup from canonical keybinds"); a real build to a temp folder (identical oc and opencode, oc vs native behavior confirmed); --revive-prepare run from source end to end; live /revive on the Mac: the build with the old binary took 5.5 s, then two unchanged-source revives skipped the build with a 0.4 s server start.
