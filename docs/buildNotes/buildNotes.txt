claude accounts:
When a Claude account hits its usage limit, oc now continues the turn on the account with the most 5-hour usage left, as last read by the sidebar, instead of the next account in the accounts list. Accounts the sidebar already shows as full for the 5-hour window or the week are skipped. Ties and accounts with no usage reading keep the list order, a fresh pool still starts on the first account, and a chat never leaves an account that still has usage. Pinned chats follow the same pick.

Under the hood: accounts.ts gained a shared usage cache reader used by startup seeding and a new failover ranker, which re-reads the caches at switch time so limit marks are no longer only read once per process. No live usage fetch. FORK.md and the wiki describe the new pick. Checks: accountPool.test.ts passed (24 pass, 0 fail) with CLAUDE_CONFIG_DIR unset; a real limit switch was not live-checked. The push runs prePush.
