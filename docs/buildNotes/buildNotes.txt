handoff prompt:
/prompt is now a built-in command. It writes a prompt you can paste into a new, empty session so another agent can carry on this session's work: the goal, the files involved, decisions made, what is done and what is left, how to check the result, and open questions. /prompt <focus> limits it to one part of the session. The turn can read files to check the paths it cites but cannot edit anything.

When the reply finishes, oc copies just the prompt, without the code fence around it, and shows "Prompt copied to clipboard". The copy happens as the run ends while the tab shows that session, also with the terminal in the background, or the first time you open the session after. Code blocks inside the prompt no longer cut it short. A reply with no prompt block shows a toast pointing to /copy. A user command file named prompt.md still replaces the built-in.

Under the hood: the command and its template live in opencode/src/command (edit denied for its turn); the TUI finds the turn by the ocCommands metadata on its user message and reads the block with CommonMark fence rules (routes/session/handoffCopy.ts, with a new test). Marking a session as viewed now waits until its messages have loaded. Checks that ran: handoffCopy.test.ts 6 pass, opencode and tui typecheck clean, a fake-model probe of the command (template, arguments, metadata, edit tools left out of the request), and a native test window on Big Pickle: /prompt listed in the slash menu, the reply's prompt copied with no fence lines (1792 characters read back from the clipboard), and "Copy last assistant message" still copies.
