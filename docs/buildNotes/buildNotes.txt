v0.2.377 wutangRapped [fix > slash menu waits on MCP]

slash menu:
Your commands and skills now show up in the / menu right after oc starts instead of waiting for every MCP server to connect, which could take seconds (up to 30 s if a server stalls). MCP prompts like /context7:... still appear a second or so later, the next time you open the menu, and typing one right after launch still works. If loading the command list fails during startup, the menu keeps what it had instead of going empty.

Under the hood: Command.state no longer awaits mcp.prompts(); MCP prompt commands load in a fiber forked in the state's scope, list() returns what has loaded, and get() joins the fiber only for names that are not command files or skills. The TUI bootstrap sends command.list with the blocking requests instead of after them and keeps the current list on a failed response. Measured on real launches (debug run): the list arrived 2.1-4.0 s after start before, 0.59-0.67 s after. Checks: typecheck clean in opencode, tui, and core; config tests 123 pass, including two new ones that fail on the old code; config, MCP, tool registry, and session prompt suites 305 pass, 1 known failure (cancel interrupts loop queued behind shell); tui suite 789 pass, 2 fail (finds Git Bash from git's cmd folder only, util.sessionTab launcher entry script) in tests that do not touch the changed files, not confirmed as pre-existing.
