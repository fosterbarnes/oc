v0.2.388 squiggleEndevors [feat. > API credit profile; fix > clipboard]

Team API credit profile:
Team plan API credit is now a Claude profile you can pick for one chat, for the next chat from Home, or for an agent; pickers mark it "bills API credits". It is never chosen automatically and never appears in the global account switch, and the last-resort rollover still asks per `claudeApiRollover`. When its credits run out, a chat pinned to it goes back to the global account and a rolled-over chat waits for a login reset. "Use global account" now sticks, so an agent's preferred account no longer re-pins the chat. The sidebar shows "Claude: <name>" with "API credits" while a chat runs on it. The key can live in the macOS Keychain or Windows Credential Manager with `"apiAccount": { "keychain": true }`, and the new **Set Claude API key** palette dialog takes a pasted key, shows its last 4 characters, saves on Enter, then clears the clipboard (clipboard history may still hold it).

Clipboard reads only on paste:
oc now reads the clipboard only on a real paste key or bracketed paste; the server, agents, remote commands and the palette can no longer make it read. Agents' cua `clipboard_read` is now blocked instead of asking.

Under the hood: accounts.ts `configureApiAccount` (dir overlap guard, one `createAccountDir` per dir), `known()` for pin/pick/state, rollover moved to a separate `apiRollover` set, `"global"` unpin sentinel, `releaseApiPin`, `poolState(..., { withApi })` with a `kind: "api"` row, and a background keychain read (`Bun.secrets`) awaited via `apiKeyReady()` in doStream and `claudePool`. turnStream.ts never switches away from the API account and handles credits-exhausted per pin/rollover. instance.ts subagent add maps the API id to its dir; SDK types regenerated. tui clipboard.ts `read(trigger)` rejects missing or keymap-synthetic triggers; prompt paste moved to `pasteFromClipboard(trigger)`; new dialogApiKey.tsx; cua.ts moves `clipboard_read` to DENIED. FORK.md and wiki Agents-and-Skills.md updated.
