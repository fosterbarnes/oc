Claude account for next Home chat:
On the Home screen, "Switch Claude account (this session)" in the oc palette now picks the Claude account for the next chat you start from the prompt. The palette entry shows the pick (or "global"), the chat is pinned to that account before its first turn, and the pick then resets. Chats started from the New oc session folder picker do not use it.

Under the hood: tui claudeCommands.tsx holds the pick in a module-level signal with takeNextSessionAccount(); the prompt's session-create path calls it after the model and agent attach and awaits claudeAccount.set(id, sessionID). No server or SDK change: pinSessionAccount only checks pool membership and the pin is read at turn start. Wiki Claude-Code.md updated.

Checks: tui typecheck clean. Throwaway WezTerm pane probe with two accounts: Home pick showed in the palette, the first turn ran on the picked account and the pool file pinned that session, and after /new a second session got no pin (1 pass; probe deleted).
