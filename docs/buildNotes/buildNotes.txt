subagents:
A subagent that hits a failing tool call, recovers, and finishes its work is no longer reported as failed. Only a tool error the subagent never answered with a reply still fails the task, such as a rejected permission that ends its turn.

Under the hood: tool/task.ts runTask failed the task when any tool part in the child's final message had an error. Claude Code runs a whole turn as one assistant message, so one early failed command (for example an ls of a file not yet written) marked a finished subagent failed; this caused 5 false "Subagent failed" results during the upstream 1.19 port. Now only a tool error after the last non-empty text part fails, and the returned text is that last non-empty text part. Added test "execute succeeds when the child answers after a failed tool call". Checks run: test/tool/task.test.ts 42 pass 0 fail; the new test and the existing terminal tool error test fail on the old task.ts and pass with the fix; prePush. This push also carries the local merge commit recording the upstream sync through a1f604bbe0 (v1.19.3).
