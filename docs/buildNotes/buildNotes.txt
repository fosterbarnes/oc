Queued prompts:
Queueing prompts with Alt+Q while an agent works no longer makes oc lag or stop accepting input, and the QUEUED strip above the prompt stays steady instead of flickering. While anything was queued, the prompt box was destroyed and rebuilt about 30 times a second (text box, key bindings, and commands each time), which caused the stutter and the "can't send until it clears" behavior. This had been happening since the queue strip was added in v0.2.314.

Under the hood: the prompt box returned several top-level pieces (a fragment) and is rendered as the fallback of a replace-mode plugin slot. opentui's Slot resolves that fallback inside its own memo, so the queue strip appearing re-ran the memo and built a new Prompt, whose empty queue snapshot hid the strip and refetched, repeating once per round trip. The Prompt now has a single root box. Debug measurements before the fix: queue add itself was fast (41-76 ms press to accepted, server handlers 1-3 ms), but the TUI refetched the queue 30-45 times a second with 598 stalls of 120-1284 ms. New test promptQueueLoop.test.ts fails with the old fragment and passes with the fix (3 of 3). Pane probe: 637 remounts in about 8 s after one Alt+Q before, 0 after. tui typecheck pass; promptQueueLoop, slashMenuLayout, queue, promptBackground, slots, keymap, app-lifecycle 20 pass; tuiPane "queues three Alt+Q presses" pass. Confirmed in the real app after a revive with 11 queued prompts.
