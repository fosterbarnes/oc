processes:
Two new Windows palette entries under Processes. Kill all AI processes (/killall) asks to confirm, then stops every oc, opencode, Claude, ChatGPT, Codex, and Cursor process and everything they started, terminal windows included. It runs in its own window so it can finish after oc closes, and lists anything that failed to stop or started again. Log AI process report (/procReport) writes the same report without stopping anything. A killai function in the PowerShell profile runs the same script when oc is frozen.

Each run writes a log and a JSON copy to %LOCALAPPDATA%\oc\killall: uptime, memory in use split into programs, kernel pools, and the rest, the top 15 processes by memory and top 10 by CPU, every matching process tree with memory, handles, age, and whether it was idle, which oc owns each claude.exe worker, helpers left behind by an oc that exited, and the System log's crash count. Processes that cannot be stopped show a short reason, and services say how to stop them as administrator.

Under the hood: killall.ps1 lives in packages/tui/src and is embedded as text, written to oc's data folder, and started with launchDetached. Parent links require the child to be created no earlier than the parent, and each stop holds the process handle and rechecks its creation time, so a reused PID is never stopped. The script keeps itself, its console, and the shells above it. Claude workers are tied to their oc server through the opencode-claude-code-<pid> temp path. Checks run: TUI typecheck, the Bun text import, live report-only runs, and the stop function on a throwaway ping (stopped, already exited, PID reuse skipped) and on lsass (access denied, nothing stopped). The user ran the installed /killall twice: everything stopped except the Codex sandbox service, which needs elevation.
