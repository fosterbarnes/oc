v0.2.299 deactivatedZippo [fix > Update all wait, PowerShell install]

Third party harness updates:
Claude and ChatGPT desktop updates now finish right after "Updated" instead of waiting 1-3 minutes. The update script was blocked deleting its temp folder, which still held the just-installed package; oc now owns that folder and removes it in the background, the same way the dependency window already did.

Updating PowerShell no longer closes oc when oc runs inside a PowerShell window. The installer's Restart Manager tried to shut down the PowerShell window hosting oc, which killed oc; the install now turns Restart Manager off, so open PowerShell windows may need a Windows restart to finish the update.

After you confirm Update all, items not yet started say "waiting", and the status switches from "needs admin approval" to "installing" once you approve.

Under the hood: the four update scripts (Claude, ChatGPT, Cursor, PowerShell) get their work folder from the caller as $WorkDir and never delete it; removeRunDir moved from dependencies.ts to desktopUpdate.ts and is shared by both paths. msiexec uses MSIRESTARTMANAGERCONTROL=Disable because DisableShutdown has no effect on a Restart Manager aware package. Checks: tui typecheck, desktopUpdate, dependencies, and updateProgress tests (46 pass, including a new test that an install removes its own temp folder), and real read-only update checks for all four scripts. Not run: a real Appx or PowerShell upgrade (nothing to update yet); whether Disable also covers the old version's uninstall step needs a VM test.
