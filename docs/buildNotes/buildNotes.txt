settings sync:
Synced or imported changes to a config file that is a shortcut (symlink) to another file now update that file instead of replacing the shortcut with a plain copy. On the Windows PC this kept the agent-push command linked to its Claude skill.

A sync change is now written whole or not at all. If Windows reports a file busy, oc retries briefly; if it still fails, the files already changed are put back, no temp files or extra backups are left, and that machine is tried again later.

An item you exclude in Sync settings now stays on that machine: it is no longer sent to your other machines either, even when you edit it there. Deleted items stay deleted, even when a machine that was offline for months comes back with an old copy. Backup copies (.bak, .bak-<anything>, .orig, and ~ files) are no longer synced, exported, or imported.

Under the hood: core OcItems.apply writes at the symlink's real path, stages every write in a temp file, renames with a short busy retry, and on failure restores only the files it changed and deletes that backup; undo shares the restore helper. OcSync.manifest and items leave out excluded items, and tombstones no longer expire. Checks: core typecheck clean; core ocItems and ocSync tests 11 pass; probes with temp homes in separate processes: symlinked command kept through apply and undo, excluded item never offered or served even after an edit, a 100-day-old delete beats a 200-day-old copy, staging and placement failures both roll back with no temp files or backup left and the next apply succeeds, backup-copy files not collected. Not checked: the Windows busy-file retry on Windows itself.
