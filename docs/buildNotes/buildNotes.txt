v0.2.348 choccieJiminy [feat. > API credit rollover; fix > queued edit]

claude accounts:
A Claude Console API key, such as the monthly API credit included with Max, Ultra, and Team plans, can now be a last resort for when every Claude login is at its usage limit. Add `apiAccount` to the claude-code provider options with the key in its own file (`{file:...}`). When a turn hits the limit and every login is limited, oc asks "Continue on API credits?" in that turn. A yes keeps that chat on the key, running the same Claude Code with the same tools, settings, and skills, until any login resets; then the chat goes back to it. Subagents never spend the key on their own. The new palette entry Claude API credit rollover switches between Ask, Always, and Off. When the credit runs out, the turn ends with "API credits used up" and waits for a login to reset.

queued messages:
Clicking a QUEUED message and choosing Edit or Delete now works while Claude is thinking or running its own tools, up to its next tool call. When it really is too late, the notice says so plainly instead of showing a raw "Session is busy" error.

Under the hood: a probe with real API credit (about half a cent) showed the plain claude CLI with ANTHROPIC_API_KEY draws the Team plan's promotional credits, so the API account is a pool-adjacent config dir (~/.claudeApi) that sets the key after the usual credential strip; it never joins pool ranking, the sidebar, the account manager, or warm-up. New oc.json key claudeApiRollover. Steers are now always held until Claude's next CLI tool call, a proxied tool's result, or the turn's result. Checks: tsgo clean in packages/opencode and packages/tui; accountPool, spawnEnv, failoverQuestion, and steering tests 59 pass after the cleanup pass; cliEvents 15 pass (one earlier run crashed with a Bun out-of-memory error, the rerun passed). fakeModel.test.ts had 2 known failures ("claudeTestFlow step 4", "an API error the CLI reports twice shows once"). Not run: a live rollover turn in oc.
