v0.2.320 yeetTuning [fix > TUI reload storm; feat. > palette descs]

Performance:
The TUI no longer lags all the time. Every config reload rewrote tui.json (an effect in tui/src/app.tsx saved palette keys on each reload), and the file watcher then reloaded every open TUI again, forever. Palette keys now save only where the user changes them, persistTuiSetting skips writes that change nothing, and the queue snapshot no longer notifies readers when its 2 s poll finds no change. The watcher in tui/src/config/live.ts now fires only when a file's mtime or size moves, because on this machine merely reading a long-idle file fired a change event. Typing / no longer fetches every command's full body: GET /command now leaves out template, which shipped every SKILL.md (about 1.1 MB here) and ran every MCP prompt on each slash-menu open. Windows already open keep lagging until oc restarts on the rebuilt build.

Queue:
Pressing Alt+Q several times in a row now queues each draft as its own entry, in order. The press used to drop while the previous add was in flight. The draft clears at the press; if the server rejects the entry, the text comes back with an error.

Command palette:
Every command in the oc section now shows a short description or its current value (Home folder, oc folder, Subagent tabs), and Subagent model/agent show "not set" instead of nothing. Added /toggleThinking, which runs the same entry as "Collapse thinking" / "Expand thinking".

Checks: tui typecheck and opencode typecheck pass; tui suite 793 pass / 0 fail; configLive.test.ts 3 pass; claudeWarmup.test.ts and usagePalette.test.ts 24 pass. New pane tests "a tui.json save reloads without the TUI rewriting the file" and "queues three Alt+Q presses sent back to back, in order" pass, and each failed on the old code. Not run: a visual check of the palette, a manual /toggleThinking run, and the lag on the real profile.
