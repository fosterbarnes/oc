v0.2.312 sauronPermarolling [feat. > new session spinner and preselect]

new session:
After you pick a folder in the Ctrl+N New oc session list, the title shows a spinner with "Creating session in <folder>" until the session opens, and the list ignores keys meanwhile, so the dialog no longer looks frozen.

Opening Ctrl+N from a session now starts the list on that session's home folder, including when the session sits in a subfolder. Typing still jumps to the best match.

Creating a session in a folder oc has not opened since it started still takes about 2 seconds: that is the server loading the project, not the picker.

docs:
The wiki Keybinds page notes that ctrl+n starts on the current session's folder. Build notes rotated to buildNotes.archive15.md.

Under the hood: the picker reuses the DialogSelect titleView spinner and locked pattern from the Move session dialog, and finds the current folder with FSUtil.contains, which ignores letter case and slash style on Windows. The planned title lookup filter was dropped after a probe showed the session list call takes about 12 ms. Checks: tui typecheck clean; ocNewSession tests 2 pass; a throwaway path probe matched backslash, forward slash, other case and subfolders; a throwaway oc TUI pane probe showed no marked row from Home, the spinner while creating, and the current folder marked from a session. Not run: the filter-then-Enter and Esc pane cases (the run was cut short).
