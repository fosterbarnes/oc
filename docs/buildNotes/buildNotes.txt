v0.2.313 pepsimanInflated [feat. > queue revive chains]

queued prompts:
Alt+Enter now queues revive chains such as /verify /revive /pass /agent-push instead of refusing them. The chain waits its turn in the queue, then runs from the oc window that has the session open. Prompts queued behind it wait for the whole chain, including across its revive, and run once it finishes.

Queued chains show in Queued prompts and can be edited or cancelled, and an entry can be edited into or out of a chain. While a chain runs, the queue reads "Paused by a revive chain". Scheduling a chain with alt+s is refused with "Revive chains cannot be scheduled". If no oc window has the session open, the chain and everything behind it wait.

docs:
The wiki Sessions page explains queued revive chains.

Under the hood: the server queue stores the chain but never sends it. When the drain reaches it, it hands the chain to one TUI waiting on the new session.queue.take endpoint and pauses the queue with a new "chain" reason; the TUI runs the steps with the existing chain code and resumes the queue at the end. A queue edit that would turn a scheduled entry into a chain is refused. The chain text helpers moved to core reviveResume.ts so the server shows entries as typed.
