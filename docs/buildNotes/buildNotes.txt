mirror oc source:
New /mirror (palette: Mirror oc source to another machine) copies this machine's oc source folder to another of your machines on the same Tailscale account: its commits, uncommitted changes, and new files. The dialog lists each machine with its oc version, "in sync" when it already matches, how many of its own changes a mirror would overwrite, and commits behind or ahead. Enter mirrors; the other machine builds for itself when it revives. oc.json mirror.dirty (ask, refuse, overwrite, backup) decides what happens to the other machine's own changes, and mirror.revive (ask, always, never) whether oc revives there afterwards; both can be changed in the dialog. mirror.hosts sets how to reach each machine over ssh (Tailscale SSH or OpenSSH). Files a previous mirror copied there do not count as the other machine's changes.

Under the hood: new core util/ocMirror.ts and hidden CLI oc oc mirror info|receive|revive, run over ssh. The sender snapshots its work tree in a temporary index (real index untouched) and sends a git bundle on ssh stdin; the target resets to the sender's commit and restores the snapshot. Changes are compared by content: each side reports its work tree as a git tree id plus diff-tree blob pairs, and only target files whose content differs from the sender's snapshot count as lost (untracked files the sender lacks stay). The target re-checks before writing. A revive request is a file in state/mirror that one oc window claims with an exclusive create, so only one window revives. Machines on the first /mirror build count every changed file as lost until updated. Checks: core, tui, and opencode tsgo --noEmit clean; ocSync and ocSource tests pass; throwaway probes through the real CLI against a fake remote covered refuse, backup, overwrite, re-mirror in sync, target edits, untracked and staged files, spaced paths, target-only commits, branch mismatch, old-format peers, and the one-window revive claim. Not run: real ssh to Windows or Tailscale SSH, the dialog, and a real remote revive.
