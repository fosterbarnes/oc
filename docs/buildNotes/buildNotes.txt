v0.2.286 boozledReviewing [feat. > revive between slash commands]

revive:
/revive, /revive-no-install, and /revive-single can now sit among other slash commands in one message, and oc runs it in order. "/revive /pass" revives, then sends /pass once oc reopens. "/pass /revive /agent-push" runs /pass, waits for that reply to finish, revives, then sends /agent-push. Free text anywhere in the message is one request every command step gets, and each step's agent is told which step it is so it does not run the later ones itself. A message can hold more than one revive.

If a step fails, you press Esc, the revive build fails, or nobody opens the session within 15 minutes of the revive, the remaining commands are not sent: they go back into an empty prompt. /revive-no-install with a revive.path script cannot report failure, so its follow-up steps always send.

slash menu:
The revive commands now show in the slash menu after other commands, and picking one types it into the message instead of restarting right away. A lone /revive from Home still restarts without creating an empty chat.

Under the hood: the TUI splits the message (prompt/slash.ts extractChain), runs the steps (reviveChain.tsx), and saves the remaining steps in a small file (core util/reviveResume.ts) that the revive pipeline marks ready or failed. The reopened TUI claims it with an exclusive-create lock, because Bun's rename on Windows lets two concurrent renames of one file both succeed. reviveCommands.tsx now exposes a reusable useRevive hook. Docs: wiki Launching page and FORK.md. Checks: tsgo for core, opencode, and tui; bun test core reviveResume (3/3), tui prompt slash and part (14/14), tui autocomplete and slash menu layout (3/3), opencode config revive (26/26).
