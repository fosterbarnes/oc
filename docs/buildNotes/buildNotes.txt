subagent reasoning levels:
A subagent entry now offers several reasoning levels instead of one entry per level, and agents call it as name:level (for example reviewer:high). Each level is on (listed to agents), manual (works only when named), or off, set in the agent file or by pressing Enter on the entry in /viewSub. Adding a subagent in /viewSub creates one entry with the chosen levels; xhigh and max start as manual. Calling an entry without a level, or with a level that is off, fails with the list of valid calls, and old per-level names like general-opus.5.5-high suggest the new form. The old variants: list in agent files is no longer supported.

Under the hood: new agent/subagentRef.ts (parse, listed, enabled, levelFor, suggest with "." and "-" as one separator, FORMAT_HINT). reasoning: Record<level, on|off|manual> added to the core agent config schema and Agent.Info; config/agent.ts turns variants:, reasoning with variant, reasoning without model, and ":" in a name into diagnostics. tool/task.ts parses the ref, validates the level against the entry and the model's variants before the permission ask, rejects a model override plus a level, and titles children @name:level. registry describeTask lists only on levels and hides entries with none; session/prompt.ts keeps levels on @name:level mentions and command agent: refs. Claude Code proxy tool defs and prompts, and the Cursor subagent catalog (one item per level, no general fallback for a ":" ref) follow the new form. subagentFile add became upsert (merges a one-line flow map, keeps a claudeAccount pin), list/owner scan {agent,agents}/**/*.md plus the configured subagentFile; httpapi POST upsert takes reasoning and list returns {name,file}; sdk regenerated; TUI dialog-subagent-efforts became dialog-subagent-reasoning, and /defaultSubagent offers name:level.
