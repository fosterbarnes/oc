v0.2.337 blechNeeed [fix > Mac Claude usage; patch > usage providers]

usage sidebar:
On a Mac, Claude usage now shows up. Claude Code keeps its login in the macOS Keychain rather than a .credentials.json file, so oc now reads it from there (and still falls back to the file). It never refreshes or writes the token.

Until you pick providers, the Usage section shows only the ones you are signed in to, so a fresh install no longer lists Cursor, OpenCode Go, or OpenRouter as "unavailable" when they were never set up. Picking any provider in Configure usage providers saves your own list as before; the new Show connected providers entry goes back to the automatic list. Saved lists are unchanged.

A provider with no data now takes one line ("not connected", "run /connect", "run claude auth login", "sign in") instead of repeating "unavailable", and "Renewal date unknown" no longer shows under a provider that has no usage data. An expired Cursor desktop login reads as signed out without sending a request that can only fail.

Under the hood: the Keychain service is "Claude Code-credentials" for the default account and gets a suffix of the first 8 hex of sha256 of CLAUDE_CONFIG_DIR otherwise. Probes return reason "no-credentials" before any request; usageProviders is optional in the sidebar settings (unset means automatic). The auth.json lookup now uses the xdg data folder oc really uses on every platform. tui typecheck passed; openSidebar tests (79) and test/cli/tui (166) passed, with new cases for Keychain service names, Keychain before file, expired Cursor desktop login, and the automatic default. Live probes on the Mac returned Claude usage from the Keychain. Plan in docs/dev/usageSidebarMac.md.
