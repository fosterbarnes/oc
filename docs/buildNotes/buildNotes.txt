v0.2.255 drangleicUndercut

revive single:
In WezTerm, /revive-single now closes the tab or pane you ran it from once the new opencode is running, leaving every other tab alone. Running it from a native opencode tab while a reply is in progress asks first, because closing that tab stops the reply. A failed build keeps the original tab open, and Windows Terminal or plain consoles behave as before.

claude chats:
A message you send while Claude is working now keeps a "read mid-turn" label after the turn ends, so you can tell it was delivered even when Claude's reply did not answer it. To get a separate answer to a new question while Claude is busy, queue it with Alt+Enter instead.

Under the hood: /revive-single passes the WezTerm pane id to the revive host, which records the original pane before the build and closes it with the existing owned-pane check after native has settled. The steered label reads the persisted steered metadata, so it survives restarts. The Claude provider log level in the user config moved from debug to info so steer and rewind evidence is not rotated away within hours. Checks run: tui and opencode typecheck, and the tuiPane "steering actions" check (1 pass). prePush runs on this push. A live WezTerm check of /revive-single needs a user build.
