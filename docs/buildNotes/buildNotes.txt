v0.2.311 dmrJinglers [feat. > queue slash commands]

queue:
Slash commands can now be queued with Alt+Q or Alt+Enter and scheduled with Alt+S. A queued /spit fix it waits its turn and then runs as that command, including scheduled sends to a fork or a new session. The queue manager shows the entry as you typed it, and editing it can add or remove commands.

Revive chains like /revive /pass and TUI commands like /btw still cannot be queued, and the warning now says which one you hit.

Queueing a prompt while an editor selection is attached no longer fails, and editing a queued entry keeps the selection.

docs:
FORK.md and the wiki Sessions page describe queued slash commands.

Under the hood: queue entries carry an optional commands list next to their parts, set by the TUI from the same paste-aware parse that Enter uses, so the server never parses typed text. One sendQueued helper serves the normal and scheduled queue paths and sends command entries through SessionPrompt.command, which now passes the queue's delivery and persisted hooks on to prompt. The queue add check allows synthetic text only as editor context, and edits keep synthetic and attachment parts. Regenerated the JS SDK. Checks: opencode and tui typecheck clean; opencode httpapiQueue and session queue tests 20 pass with new cases for editor context, bare commands, and a queued command sent through its command; tui queue, slash and part tests pass; prompt.test.ts 68 pass with 3 known failures (queue contention, 2 handoff child).
