v0.2.380 freebasedFractal [feat. > account sync; fix > missed warm-ups]

claude accounts:
Each Claude account's friendly name and warm-up schedule are now stored by the account's email and synced between your machines over tailnet sync. The same account gets the same name on every machine, even when its folder is ~/.claude on one and ~/.claude2 on another. No sign-in data is synced. Your existing names and schedules move over automatically the first time the new build runs, and removing an account folder on one machine no longer clears its name elsewhere.

warm-ups:
Each scheduled warm-up is now sent once, by whichever machine is up and signed in to that account. When both are, goonstation goes first and the Mac steps in a minute later only if goonstation didn't send. Warm-ups that came due while the Mac slept used to be dropped without a trace; now, after a wake or an oc restart, a warm-up missed in the last 5 hours is sent then, unless another machine already sent it. The warm-up dialog shows which machine sent the last warm-up and marks accounts that aren't signed in on this machine.

Under the hood: new warm-up modules (synced accounts, folder-to-email identities, peer views, legacy migration) and a rewritten scheduler with a pending queue, host ranking, standby waits and a 5-hour catch-up window. A new GET /oc-sync/warmup peer route shares signed-in emails, claims and outcomes. The runtime store is now warmup-state.json; the old warmup.json is read once for migration. claudeAccountNames is machine-only and no longer synced. oc.json writes from the server (OcConfig.edit) and the TUI now take OC_CONFIG_LOCK, re-read inside it, and keep comments. The migration barrier waits only on peers that run oc, so tailnet devices without oc (winserver, Home Assistant) no longer hold it for 15 minutes. Six scheduler and migration gaps found in review are fixed and covered by tests. Checks: typecheck clean in core, opencode and tui (opencode rerun before push); warm-up suites 149/0 after the review fixes; TUI warm-up 30/0; core ocItems/ocSync 14/0; pane warm-up 1/0; claude-code, listener, global and config tests 1094 pass, 1 known failure (test/config/tui.test.ts keybind lookup, also fails without these changes). Live two-machine check with the Mac and win10 on 0.2.380: accounts identical on both, each machine's peer route answers the other, and a test slot was sent once by goonstation while the Mac recorded it.
