# Agent test

Read before `/agentTest` or a live check of an oc TUI change.

`/agentTest` and live checks of oc TUI changes run native `opencode.exe` built from this checkout, not `oc.exe`: a built but not installed `oc.exe` refuses to start while the installed resident server runs ("running from another oc install", `config/resident.ts`). `.scripts\nativeTest.ps1` owns the window:
- `-Start -Build` builds only `dist\opencode-native-windows-x64` (nothing is installed), creates a throwaway git project in `C:\ocTestTmp\agentTest\<stamp>` (`-Project <dir>` for a real repo), and opens it in its own `wezterm-gui` process (`start --always-new-process`, the user's wezFig config, `⦿` tab). It strips the agent shell's `OPENCODE*`/`OC_*`/`CLAUDE*`/`WEZTERM_*`/`AGENT` vars so the window starts like a fresh tab, then prints the run (`guiPid`, socket, pane) and records it in `C:\ocTestTmp\agentTest\current.json`. One run at a time.
- `-Screen` prints the visible text (trailing padding trimmed) through that GUI's own socket (`gui-sock-<pid>`). The WezTerm accessibility tree has no terminal text, so judge results on screen text and use screenshots only as evidence.
- `-Stop` stops only that run's process tree (CIM identity, leaves first) and deletes the throwaway project (`ownsProject`); a `-Project` folder is kept. Always run it, also after failures.
- Shared state: `-Start` copies `model.json`, `kv.json`, `agent.json`, `frecency.jsonl`, `tui.json`, and `claude-code\account-pool.json` to `C:\ocTestTmp\agentTest\state`; `-Stop` restores each file whose hash changed and lists them. A whole-file restore also reverts the user's own oc writes to those files during the run. Not covered: `prompt-history.jsonl` and `claude-code\sessions.json` (the user's oc appends to them constantly).
- Native has no "Reload oc config"; a project `opencode.jsonc` change needs `-Stop` and `-Start`. A permission answered "Allow always" in the test window is saved for that project and stops asking.
- Input and reads go through the user-level tool `ocTui` (`~/.config/opencode/tool/ocTui.ts`; global `permission` denies it, `agentTester` and the `/agentTest` command allow it; listed in `proxyOpencodeTools` so Claude Code models get it too). It sends keys, text, SGR mouse clicks, and wheel straight into the run's pane with `wezterm cli send-text` (no focus, no takeover) and returns the screen; steps `press`, `type`, `paste`, `palette`/`ocPalette` (exact title, Enter only when the top row starts with it), `pick` (same for any open list dialog), `click`, `scroll`, `wait`, `gone`, `expect`, `expectGone`, `reply` (waits for the chat turn to finish and judges only the last reply). Screen text has no colors, so the highlighted list row is invisible: rows are chosen with `pick`. Recipes for the basic actions: `~/.config/opencode/agentTest/ocTuiRecipes.md`. Keys are legacy VT only: once ConPTY receives one win32-input-mode sequence, a bare Esc stops closing dialogs, so never mix encodings. Kitty-only chords (ctrl+m, ctrl+enter, shift+enter, ctrl+shift+<key>) are rejected; use the palette title or the ctrl+x leader form, or cua foreground input under a takeover for cases about WezTerm's own key handling. A new or edited `ocTui` or config entry reaches running chats only after an oc server restart (ctrl+o "Restart"): "Reload oc config" reloads the TUI tab's launch folder, not the open chat's folder.
- Briefs: give each case as `ocTui` steps ending in `expect` lines with exact text (ctrl+o oc palette, ctrl+p command palette). `/agentTest ... model=<provider/model#variant>` swaps the tester model for one run.
- It runs on the real profile: real `oc.db`, accounts, models (plan usage), and shared state (`model.json`, `kv.json`, `agent.json` current agent, prompt history). Cases must not press Enter in the main prompt, change model or variant, or cycle agents unless that is the test. Sessions stay in the session list under the throwaway project. Stop a run before rebuilding: the running exe is locked.
- Not testable this way (needs the resident server): server shutdown/restart, subagent tabs, `--shutdown-all`, revive. Those need an install and the user.
